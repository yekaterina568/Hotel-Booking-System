# Двойное бронирование, продление брони, возврат денег

## 1. Защита от двойного бронирования

Один номер нельзя забронировать двум гостям на пересекающиеся даты. Защита в два слоя:

1. **Блокировка номера в приложении.** `BookingService.create` и `extend` сначала блокируют строку номера
   (`SELECT … FOR UPDATE`, метод `BookingRepository.lockRoom`), потом проверяют пересечения.
   Два одновременных запроса на один номер выполняются по очереди, и второй видит бронь первого → `409`.
2. **Ограничение в базе данных** (миграция `006`): `EXCLUDE USING gist` по `room_id` и периоду
   `[expected_arrival, expected_departure)` для броней в статусах `CONFIRMED` и `CHECKEDIN`.
   Даже если проверку в коде обойти, PostgreSQL не сохранит пересекающуюся бронь.
   `DatabaseConflictErrors` превращает эту ошибку в `409 "Номер уже занят на эти даты"` вместо `500`.

Периоды полуоткрытые: выезд в 12:00 и заезд другого гостя в 12:00 того же дня — не пересечение.

Миграция `006` перед созданием ограничения отменяет (`CANCELLED`) более поздние брони, которые уже пересекаются
в старых данных, иначе ограничение не создастся.

## 2. Продление брони

`POST /api/bookings/{id}/extend`, тело: `{"newDeparture": "2026-12-05T12:00:00+05:00"}`

| Условие | Ответ |
|---|---|
| Нет новой даты | 400 |
| Бронь не `CONFIRMED` и не `CHECKEDIN` | 409 |
| Новая дата не позже текущей или уже в прошлом | 400 |
| Всего больше 30 ночей (`MAX_STAY_NIGHTS`) | 400 |
| Номер занят на добавленные ночи | 409 + с какой даты занят и до какой даты можно продлить |
| Всё в порядке | 200 + бронь с новыми `nights` и `totalPrice` |

Лимит 30 ночей действует и при создании брони.

На фронтенде: раздел **New Booking → Manage a Booking** (просмотр, продление, отмена).

## 3. Возврат денег по правилам отмены

Стоимость брони = ночи × `price_per_night` номера. Процент зависит от того, за сколько до заезда отменили
(время отмены сохраняется в новой колонке `bookings.cancelled_at`):

| Отмена до заезда | Возврат |
|---|---|
| 7 дней и больше | 100% |
| от 3 до 7 дней | 50% |
| меньше 3 дней или после заезда | 0% |

Правила (`RefundPolicy`):
- возврат только по **отменённой** брони;
- **один** возврат на бронь (возврат в статусе `FAILED` можно повторить);
- сумма считается сервером.

API:
- `GET /api/bookings/{id}/refund/quote` — сколько вернут и почему (ничего не сохраняет; для неотменённой брони
  показывает, сколько вернут, если отменить сейчас);
- `POST /api/bookings/{id}/refund`, тело необязательно: `{"reason": "…"}` — оформляет возврат (`COMPLETED`);
- `POST /api/refunds` (ручной ввод) теперь тоже проверяет: сумма > 0 (исправлен BUG-2), бронь отменена,
  возврата ещё не было, сумма не больше положенной по правилам.

На фронтенде: раздел **Billing & Refunds** — кнопка Calculate показывает расчёт, Issue Refund оформляет возврат.
